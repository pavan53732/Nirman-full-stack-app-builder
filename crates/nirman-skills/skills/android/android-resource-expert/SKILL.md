# Android Resource Expert

Scope: the Android resource system — how resources are qualified and resolved,
drawables and vectors, themes and styles, string and plural resources, resource
shrinking, and resolving merge and qualification conflicts (BS §79.7).

## Trigger
Resources must resolve correctly across configurations, or a resource
problem is suspected: a wrong variant chosen, a missing translation fallback, a
merge conflict, or a shipped resource that should have been removed.

## Required capabilities
- `ANDROID_BUILD_TOOLCHAIN`
- `ANDROID_SOURCE_ENGINEERING`
- `ANDROID_RELEASE_VALIDATION`

## Preconditions
- The current EnvironmentCapabilityRecord is available and not stale; capability
  is read from the record, never assumed.
- `ANDROID_SOURCE_ENGINEERING` resolves to AVAILABLE for static analysis.
- The configurations in scope are known: locales, densities, themes, and
  night mode where they matter.

## Context requirements
- The configurations the app must resolve correctly under.
- Which resources are qualified, and on which qualifier.
- Revision, artifact digest where one exists, and the environment fingerprint of
  the session, so every record binds to them.
- Whether resource shrinking is enabled for the variant under review.

## Allowed tools
- resource_merger
- static_analyzer
- managed_emulator

## Procedure
1. Inventory the qualified resources and confirm each qualifier set is one the
   platform can actually resolve, rather than a combination that silently falls
   back.
2. Confirm a sensible default exists in the unqualified bucket for every
   qualified resource, so a configuration with no match still resolves.
3. Check theme and style layering: prefer theme attributes over hard-coded
   values, and confirm night and high-contrast variants resolve where they ship.
4. Prefer vectors and density-independent assets for icons and simple shapes,
   and reserve raster assets for content that genuinely needs them.
5. Check strings and plurals are complete per locale and that plural and gender
   rules are generated by rule rather than concatenated in code.
6. Run resource shrinking and confirm what was removed, so a resource reached
   only reflectively is not silently dropped.
7. Resolve merge conflicts at the owning source and record which variant won.

## Evidence
- The qualified resource inventory and the configurations each resolves under.
- Missing-default findings: qualified resources with no unqualified fallback.
- Shrinking results: what was removed and what was kept, with the reason.
- Per-locale completeness for strings and plurals.
- Every record bound to revision and artifact digest.

## Failure classification
- - BLOCKED — a required capability resolves to UNAVAILABLE or USER_REQUIRED;
  the gated steps MUST NOT execute and the blocked state MUST be reported.
- UNRESOLVABLE_QUALIFIER — a qualifier combination the platform cannot
  resolve, causing a silent fallback.
- MISSING_DEFAULT — a qualified resource has no unqualified fallback.
- SHRINKER_DROPPED_IN_USE — shrinking removed a resource the app reaches.
- MERGE_CONFLICT — the same resource is defined inconsistently across sources.

## Recovery
- A missing default is added rather than relying on the configuration that
  happened to resolve during testing.
- A resource dropped by shrinking is either kept with a scoped rule or its
  reflective access is removed; a blanket keep-all is not the fix.
- A merge conflict is resolved at the owning source, and the winner recorded,
  rather than by duplicating the resource to override it.
- One retry is permitted after a materially changed input; an identical
  analysis is never re-run against unchanged evidence.

## Output contract
Emits `ResourceResult` (§23 SkillPackage contract):

- qualifiedInventory: resources, qualifiers, and resolved configurations
- missingDefaults: qualified resources with no fallback
- shrinkResults: removed and kept, with reasons
- localeCompleteness: per-locale strings and plurals
- classification: one of the classes above, null on success
- evidenceRefs: identifiers of the captured resource evidence

## Fixtures
- Resource resolves correctly across declared configurations
- Qualified resource with no default
- Shrinking removes a resource the app reaches
- Merge conflict resolved at the owning source
- Night and high-contrast variants resolving
- Capability UNAVAILABLE — blocked, nothing analysed

This skill is permission-neutral (CLAUSE.SKILL.NO_PERMISSION_GRANT); every
execution still passes through ToolBroker and PolicyAuthority.
