# Android Localization Expert

Scope: Making an app correct in more than one language — string resource
externalization, locale and region qualification, right-to-left mirroring,
plural and gendered grammar, locale-correct date, number, and currency
formatting, per-locale app resources, and pseudo-locale verification (BS §79.7). This skill provides the domain knowledge
that the `UI Worker` and `Android Data and Integration Worker` consume.

Gated by ANDROID_BUILD_TOOLCHAIN and ANDROID_SOURCE_ENGINEERING. When it resolves to UNAVAILABLE or USER_REQUIRED,
the gated steps MUST NOT execute and the blocked state MUST be
reported. This skill does not replace a worker role — it provides
domain-specific instruction that the worker executes within its
scoped asset transaction (BS §50).

## Workflow
1. Externalize every user-visible string into string resources; no
   literal text remains in layout or composable code that a translator
   cannot reach.
2. Qualify resources by locale and region: values-b+es+419 for regional
   variants, values-night and smallestWidth where the difference is not
   linguistic but spatial.
3. Use ICU message format for plurals, gender, and selects so the
   grammar of each language is generated by rule rather than by string
   concatenation.
4. Mirror the layout for RTL: prefer start and end over left and right,
   set the layout direction from the locale, and verify that icons whose
   meaning is directional are mirrored while brand marks are not.
5. Format through the platform locale: dates, times, numbers, and
   currency are formatted for the user's locale, never for a hard-coded
   default.
6. Handle text expansion: German and Finnish routinely exceed English by
   a third, so layouts must reflow and never clip or truncate silently.
7. Verify with pseudo-locales: run the app in the accented and
   right-to-left pseudo-locales on the Nirman-managed emulator and
   confirm that no screen clips, overlaps, or shows an untranslated
   literal.

## Invariants
- No user-visible string is concatenated at runtime; a sentence is one
  message with placeholders, never fragments joined in code.
- Directional layout uses start and end; absolute left and right in a
  user-facing layout is a defect.
- Formatting is locale-driven; a hard-coded date, number, or currency
  pattern is a defect.
- A locale the app does not ship is reported as unsupported, never
  silently rendered in the fallback language.
- Every localized screen is verified, not assumed: an unverified locale
  is reported as unverified.
- The skill is permission-neutral (CLAUSE.SKILL.NO_PERMISSION_GRANT); every
  execution still passes through ToolBroker and PolicyAuthority.
