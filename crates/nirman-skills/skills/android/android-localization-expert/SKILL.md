# Android Localization Expert

Scope: Making an app correct in more than one language — string resource
externalization, locale and region qualification, right-to-left mirroring,
plural and gendered grammar, locale-correct date, number, and currency
formatting, per-locale app resources, and pseudo-locale verification (BS §79.7). This skill provides the domain knowledge
that the `UI Worker` and `Android Data and Integration Worker` consume.

## Trigger
This skill is requested when making an app correct in more than one language — string resource externalization, locale and region qualification, right-to-left mirroring, plural and gendered grammar, locale-correct date, number, and currency formatting, per-locale app resources, and pseudo-locale verification (BS §79.7). This skill provides the domain knowledge that the `UI Worker` and `Android Data and Integration Worker` consume.. It does not replace a worker role — it supplies the domain

## Procedure
1. Externalize every user-visible string into string resources; no
   literal text remains in layout or composable code that a translator
   cannot reach.
2. Qualify resources by locale and region: values-b+es+419 for regional
   variants, values-night and smallestWidth where the difference is not
   linguistic but spatial.
3. Use ICU message format for plurals, gender, and selects so the
   grammar of each language is generated by rule rather than by string
   concatenation.
4. Mirror the layout for RTL: prefer start and end over left and right,
   set the layout direction from the locale, and verify that icons whose
   meaning is directional are mirrored while brand marks are not.
5. Format through the platform locale: dates, times, numbers, and
   currency are formatted for the user's locale, never for a hard-coded
   default.
6. Handle text expansion: German and Finnish routinely exceed English by
   a third, so layouts must reflow and never clip or truncate silently.
7. Verify with pseudo-locales: run the app in the accented and
   right-to-left pseudo-locales on the Nirman-managed emulator and
   confirm that no screen clips, overlaps, or shows an untranslated
   literal.

## Evidence
- A record of each procedure step that executed, with the outcome observed,
  bound to the source revision and the environment fingerprint.
- The emitted `LocalizationResult` (§23 SkillPackage contract), carrying its
  classification and its evidence references.
- Invariant claims this skill must leave observable, each of which is a
  statement the evidence above has to support:

  * No user-visible string is concatenated at runtime; a sentence is one
  *   message with placeholders, never fragments joined in code.
  * Directional layout uses start and end; absolute left and right in a
  *   user-facing layout is a defect.
  * Formatting is locale-driven; a hard-coded date, number, or currency
  *   pattern is a defect.
  * A locale the app does not ship is reported as unsupported, never
  *   silently rendered in the fallback language.
  * Every localized screen is verified, not assumed: an unverified locale
  *   is reported as unverified.
- Every claim reduced to an observable: what was seen, on which device or
  host, at which revision — never a statement of intent.

## Failure classification
- BLOCKED — a required capability resolves to UNAVAILABLE or USER_REQUIRED;
  the gated steps MUST NOT execute and the blocked state MUST be reported.
- PRECONDITION_UNMET — a precondition below was not satisfied; the skill
  does not proceed past it.
- ACTION_FAILED — a procedure step was attempted and did not produce its
  expected outcome.
- INVARIANT_VIOLATED — the work completed but one of the invariant claims
  this skill must leave observable does not hold.
- TIMEOUT — a wait exceeded its bound; an unbounded wait is a hang, not a
  slow step.

- HARDCODED_STRING — a user-visible string remains outside string resources.
- LAYOUT_NOT_MIRRORED — the layout uses left and right rather than start and end, so it does not mirror for RTL.
- TEXT_CLIPPED_ON_EXPANSION — a translated string expands past its layout and is clipped.
- PLURAL_RULE_WRONG — plurals are not ICU-formatted, so the target language's plural rules are not honoured.

## Recovery
- A blocked capability resumes when the capability record changes; the blocked
  node names its resume condition and is never reported as a failure of the
  goal.
- One retry is permitted after a repair that materially changed the input. An
  identical action is never re-run against unchanged evidence, and the
  recoveryAttemptPolicy bound escalates rather than terminating the goal.
- An invariant violation is repaired at its cause, never by relaxing the check
  that detected it.
- Nothing unverified is reported as verified; an unverified outcome is
  reported as unverified.

## Output contract
Emits `LocalizationResult` from `LocalizationResultRequest` (§23 SkillPackage contract):

- classification: one of the failure classes above, null on success
- evidenceRefs: identifiers of the evidence this run captured
- revision and, where one exists, artifactDigest: what the evidence is bound to
- unverified: outcomes this run could not verify, named rather than assumed
